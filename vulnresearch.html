01 / CLASSES

Six classes.
Infiniment de bugs.

CLASS 01 · DÉBUTANT
Buffer Overflow
Écriture au-delà des limites d'un buffer alloué. Stack (ret addr) ou heap (metadata). Classe fondatrice de l'exploitation moderne.
CLASS 02 · DÉBUTANT
Integer Overflow
Débordement d'un entier qui tronque une valeur critique — souvent la taille d'une allocation. Mène typiquement à un heap overflow.
CLASS 03 · INTERMÉDIAIRE
Race Condition / TOCTOU
Fenêtre temporelle entre une vérification et une action. Exploitable via deux threads en concurrence sur une ressource partagée.
CLASS 04 · INTERMÉDIAIRE
Out-of-Bounds R/W
Accès à un indice hors des bornes allouées. En lecture : info leak. En écriture : corruption de données adjacentes.
CLASS 05 · AVANCÉ
Use-After-Free
Utilisation d'un pointeur vers de la mémoire déjà libérée. Nécessite de comprendre les allocateurs (slab, PartitionAlloc) pour être exploité.
CLASS 06 · EXPERT
Type Confusion / JIT
Le moteur JS utilise un mauvais type pour accéder à un objet. Les bugs JIT impliquent des élisions incorrectes de bounds checks par le compilateur.
CLASS 07 · INTERMÉDIAIRE
Logic Bug
Erreur de logique sans memory corruption. Ex : mauvaise initialisation de flags (Dirty Pipe). Impact souvent aussi critique que les bugs mémoire.
CLASS 08 · AVANCÉ
Parsing Bug
Vulnérabilité dans le traitement d'un format (image, archive, protocole). libwebp 2023 en est l'exemple moderne le plus étudié.

03 / QEMU LAB

Setup
QEMU
complet.

Tout le process pour créer et gérer des VMs vulnérables avec QEMU sur Linux Mint 4GB RAM. Chaque étape est testée et correspond aux bugs du référentiel.

01
INSTALLATION DE QEMU + OUTILS
Installe QEMU KVM avec les outils essentiels. Sur Mint la virtualisation KVM est disponible si ton CPU supporte VT-x/AMD-V (vérifie avec egrep).
# Vérifier le support matériel egrep -c '(vmx|svm)' /proc/cpuinfo # Résultat > 0 = KVM disponible sudo apt install -y qemu-kvm qemu-utils \ virtinst virt-manager libvirt-daemon-system \ cloud-image-utils gdb sudo usermod -aG kvm,libvirt $USER # Re-login nécessaire après
⚠ Avec 4GB RAM, alloue 1.5–2GB max par VM. Ne lance jamais deux VMs simultanément.
02
CRÉER UNE VM KERNEL VULNÉRABLE (ex: Ubuntu 16.04)
Télécharge une image cloud ou ISO minimal. Ubuntu 16.04 couvre Dirty COW, Baron Samedit et les bugs kernel 2016–2021.
# Télécharger une image cloud légère wget https://cloud-images.ubuntu.com/xenial/current/\ xenial-server-cloudimg-amd64.img # Redimensionner le disque (10GB suffisent) qemu-img create -f qcow2 -F qcow2 -b \ xenial-server-cloudimg-amd64.img ubuntu1604.qcow2 10G # Créer le fichier cloud-init (user: vuln / pass: vuln) cat > user-data.yaml <<EOF #cloud-config users: - name: vuln passwd: \$6\$rounds=4096\$salt\$hash sudo: ALL=(ALL) NOPASSWD:ALL shell: /bin/bash EOF cloud-localds seed.iso user-data.yaml
03
LANCER LA VM (commande de base)
Lance la VM avec KVM activé, 1.5GB RAM, et SSH forward sur le port 2222. Adapte -smp selon ton nombre de cores.
qemu-system-x86_64 \ -enable-kvm \ -m 1536 \ -smp 2 \ -hda ubuntu1604.qcow2 \ -cdrom seed.iso \ -net nic \ -net user,hostfwd=tcp::2222-:22 \ -nographic # Connexion SSH depuis l'hôte : ssh -p 2222 vuln@localhost
💡 -nographic = sortie console dans le terminal, pas de fenêtre GUI. Idéal pour économiser la RAM. Ctrl+A puis X pour quitter.
04
KERNEL DEBUGGING AVEC GDB (mode kernel)
Pour les bugs kernel, ajoute les flags de debug à QEMU et attache gdb depuis l'hôte via le stub intégré. Indispensable pour observer le comportement réel.
# Lancer QEMU avec le stub gdb activé qemu-system-x86_64 \ -enable-kvm \ -m 1536 \ -smp 2 \ -hda ubuntu1604.qcow2 \ -net nic -net user,hostfwd=tcp::2222-:22 \ -s \ # ouvre gdbserver sur :1234 -S \ # pause au démarrage -nographic # Dans un autre terminal, attacher gdb : gdb vmlinux # le binaire kernel avec symboles (gdb) target remote :1234 (gdb) continue
📦 Pour obtenir vmlinux avec symboles : installe linux-image-$(uname -r)-dbgsym dans la VM, puis copie via scp.
05
ACTIVER KASAN (détection UAF/OOB en kernel)
Kernel Address Sanitizer est le meilleur outil pour observer des bugs UAF et OOB dans le kernel. Il faut recompiler le kernel avec KASAN activé.
# Dans la VM, récupérer les sources du kernel apt-get source linux-image-$(uname -r) cd linux-*/ # Activer KASAN dans la config scripts/config --enable CONFIG_KASAN scripts/config --enable CONFIG_KASAN_INLINE scripts/config --set-val CONFIG_KASAN_SHADOW_OFFSET 0xdffffc0000000000 # Compiler (long, ~30min) make -j$(nproc) bzImage make -j$(nproc) modules # Boot sur le nouveau kernel dans QEMU qemu-system-x86_64 -kernel arch/x86/boot/bzImage \ -append "root=/dev/sda console=ttyS0 kasan=1" ...
06
TRANSFERT DE FICHIERS HÔTE ↔ VM
Pour copier tes scripts de reproduction dans la VM et récupérer les crashlogs.
# Copier un fichier vers la VM scp -P 2222 repro.c vuln@localhost:~/ # Récupérer un fichier depuis la VM scp -P 2222 vuln@localhost:~/crash.log ./ # Monter un dossier partagé via virtfs (plus rapide) qemu-system-x86_64 ... \ -virtfs local,path=/home/toi/share,\ mount_tag=host0,security_model=mapped,id=share # Dans la VM : mount -t 9p -o trans=virtio host0 /mnt/share
07
SNAPSHOTS — REVENIR À UN ÉTAT PROPRE
Les snapshots QEMU te permettent de sauvegarder l'état d'une VM et d'y revenir après un crash, sans refaire l'installation.
# Créer un snapshot (VM éteinte) qemu-img snapshot -c clean_state ubuntu1604.qcow2 # Lister les snapshots qemu-img snapshot -l ubuntu1604.qcow2 # Restaurer un snapshot qemu-img snapshot -a clean_state ubuntu1604.qcow2 # Snapshot "live" (VM allumée, via monitor) # Ajoute -monitor stdio au lancement puis : (qemu) savevm before_test (qemu) loadvm before_test
💡 Workflow recommandé : installe la VM → snapshot "base" → installe les outils → snapshot "ready" → teste un bug → loadvm ready → teste suivant.
08
VM BROWSER (Firefox ancien)
Pour les bugs Firefox/Chromium anciens, une VM légère suffit. Utilise une image Debian minimal avec Xvfb pour le rendu sans GUI complète.
# Télécharger Firefox ancien via archive Mozilla wget "https://ftp.mozilla.org/pub/firefox/releases/\ 50.0/linux-x86_64/en-US/firefox-50.0.tar.bz2" tar xf firefox-50.0.tar.bz2 # Lancer avec affichage virtuel (économise RAM) apt install xvfb x11vnc Xvfb :99 -screen 0 1024x768x24 & export DISPLAY=:99 ./firefox/firefox & # Accès depuis l'hôte via VNC forwarded qemu-system-x86_64 ... \ -net user,hostfwd=tcp::5900-:5900 # Connecte un client VNC sur localhost:5900
🔒 Ne jamais exposer ces VMs sur le réseau. Le forward localhost uniquement est suffisant et safe.
